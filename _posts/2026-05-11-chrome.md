# 告别频繁切屏！Claude Code 携手 Chrome，让 AI 直接在浏览器里帮你干活

作为开发者，你是否厌倦了这种循环：在终端写代码 -> 切到浏览器测试 -> 发现报错 -> 切回终端查日志 -> 修改代码 -> 再切回浏览器刷新？这种频繁的上下文切换不仅打断心流，更拖慢了交付速度。

今天我们要聊的 Claude Code Chrome 集成功能，正是为了彻底终结这种割裂的体验。通过连接 CLI 与你的浏览器，Claude 现在可以直接打开网页、读取控制台、填写表单，甚至操作你已经登录的 Web 应用。写完代码，让 AI 自己去浏览器里验证，你只需在终端坐享其成。

## 关键概念：无缝的浏览器控制权

Claude Code 通过 [Claude in Chrome 浏览器扩展](https://chromewebstore.google.com/detail/claude/fcoeoabgfenejglbffodgkkbkcdhcgfn) 实现了从命令行（CLI）或 VS Code 扩展直接操控浏览器的能力。它的核心亮点在于：

- **共享登录态**：Claude 会打开新的标签页，并共享你浏览器原有的登录状态。这意味着它可以无缝访问你的 Google Docs、Notion 或内部后台，无需配置复杂的 API。
- **实时可见操作**：所有浏览器动作都在可见的 Chrome 窗口中实时执行，你完全拥有掌控权。
- **智能暂停**：当遇到登录页或验证码（CAPTCHA）时，Claude 会自动暂停并提示你手动处理，绝不会盲目乱撞。

> **注意**：该功能目前处于 Beta 阶段，仅支持 Google Chrome 和 Microsoft Edge。Brave、Arc 等其他 Chromium 内核浏览器暂不支持，WSL（Windows Subsystem for Linux）也不在支持范围内。

## 实操演示：从启动到自动化

### 1. 环境准备

在开始之前，请确保满足以下条件：
- 安装 [Google Chrome](https://www.google.com/chrome/) 或 [Microsoft Edge](https://www.microsoft.com/edge)
- 安装 [Claude in Chrome 扩展](https://chromewebstore.google.com/detail/claude/fcoeoabgfenejglbffodgkkbkcdhcgfn)（版本需 >= 1.0.36）
- 安装 Claude Code（版本需 >= 2.0.73）
- 拥有 Anthropic 的直接订阅计划（Pro, Max, Team 或 Enterprise）。*注意：通过 Amazon Bedrock 等第三方提供商访问的用户无法使用此功能。*

### 2. 启动连接

在 CLI 中启动 Claude Code 时，加上 `--chrome` 参数即可：

```bash
claude --chrome
```



![Cli Chrome Launch](assets/images/screenshots/cli-chrome-launch.png)



如果你已经在会话中，也可以随时输入 `/chrome` 来启用或检查连接状态。

### 3. 典型应用场景

一旦连接成功，你就可以用自然语言将编码任务与浏览器操作串联起来：

**本地 Web 应用测试**
当你刚修改完表单验证逻辑，不想自己点点点时：
```text
I just updated the login form validation. Can you open localhost:3000,
try submitting the form with invalid data, and check if the error
messages appear correctly?
```

**基于控制台的实时调试**
让 Claude 直接去浏览器看控制台报错，然后回来改代码：
```text
Open the dashboard page and check the console for any errors when
the page loads.
```

**自动化表单填写**
读取本地 CSV，自动在 CRM 系统中录入数据：
```text
I have a spreadsheet of customer contacts in contacts.csv. For each row,
go to the CRM at crm.example.com, click "Add Contact", and fill in the
name, email, and phone fields.
```

**在 Google Docs 中起草内容**
无需调用文档 API，直接利用你的登录态进行撰写：
```text
Draft a project update based on the recent commits and add it to my
Google Doc at docs.google.com/document/d/abc123
```

**网页数据提取**
将网页上的非结构化信息提取为本地结构化文件：
```text
Go to the product listings page and extract the name, price, and
availability for each item. Save the results as a CSV file.
```

**录制操作 GIF**
自动生成操作演示动图，产品文档必备：
```text
Record a GIF showing how to complete the checkout flow, from adding an
item to the cart through to the confirmation page.
```

## 进阶技巧与排错指南

### 设为默认启用

每次都加 `--chrome` 太麻烦？在会话中运行 `/chrome` 并选择 "Enabled by default" 即可。在 VS Code 扩展中，只要安装了 Chrome 扩展就默认可用。

> **提示**：默认启用 Chrome 会增加上下文窗口（context window）的消耗，因为浏览器工具集会一直被加载。如果发现上下文消耗过快，建议关闭默认启用，仅在需要时使用 `--chrome`。

### 权限管理

站点级别的权限继承自 Chrome 扩展。你可以在扩展设置中精细控制 Claude 允许浏览、点击和输入的网站范围。

### 常见问题排查

- **扩展未检测到**：首次启用时，Claude Code 会安装原生消息主机配置文件，Chrome 需要在启动时读取它。如果首次连接失败，**重启 Chrome** 通常就能解决。如果依然不行，运行 `/chrome` 选择 "Reconnect extension"。
- **浏览器无响应**：通常是因为页面弹出了模态对话框（alert/confirm），阻塞了浏览器事件。手动关闭弹窗，然后告诉 Claude 继续。
- **长会话连接断开**：Chrome 扩展的 Service Worker 在长时间不活动后会休眠。此时运行 `/chrome` 重新连接即可。

常见错误速查表：

| 错误信息 | 原因 | 解决方案 |
|---|---|---|
| "Browser extension is not connected" | 原生消息主机无法连接到扩展 | 重启 Chrome 和 Claude Code，运行 `/chrome` 重连 |
| "Extension not detected" | 扩展未安装或被禁用 | 在 `chrome://extensions` 中安装或启用扩展 |
| "No tab available" | Claude 在标签页准备好之前尝试操作 | 让 Claude 创建新标签页后重试 |
| "Receiving end does not exist" | 扩展 Service Worker 休眠 | 运行 `/chrome` 选择 "Reconnect extension" |
